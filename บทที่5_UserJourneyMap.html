1. บทนำ

“ปัญหาที่แย่ที่สุดของผู้ใช้ มักไม่ได้อยู่ที่หน้าจอใดหน้าจอหนึ่ง แต่อยู่ที่ ‘รอยต่อ’ ระหว่างขั้นตอน” — เราจะมองเห็นรอยต่อที่มองไม่เห็นเหล่านั้นได้อย่างไร?

ในบทที่ 4 เราสร้าง Persona และ Empathy Map ซึ่งเป็นภาพ “โลกภายในของผู้ใช้ในภาพรวม” แต่ภาพนั้นยังเป็นภาพนิ่ง บทนี้จะนำภาพนั้นมา “กางออกตามแกนเวลา” ด้วย User Journey Map เพื่อดูว่าอารมณ์และอุปสรรคของผู้ใช้เกิดขึ้นตรงจุดไหนของเส้นทาง ตั้งแต่ต้นจนจบ

Journey Map ช่วยให้ทีมเห็นประสบการณ์แบบ end-to-end ไม่ใช่แค่ทีละหน้าจอ ทำให้ค้นพบว่าควรลงมือออกแบบแก้ที่จุดใดก่อน ซึ่งเป็นทักษะการวิเคราะห์ (Analyze) ที่เป็นหัวใจของบทนี้

💭 ชวนคิดก่อนเริ่ม
เส้นทางของ “พิม” ตั้งแต่รู้ว่าน้องหมาหายจนได้กลับคืน น่าจะมีกี่ช่วง? และในช่วงไหนที่เธอน่าจะรู้สึกแย่ที่สุด — จุดนั้นแหละคือโอกาสที่แอปของเราจะสร้างคุณค่าได้มากที่สุด

2. เนื้อหาหลัก

2.1 User Journey Map คืออะไร

User Journey Map (แผนผังการเดินทางของผู้ใช้) คือภาพที่แสดงลำดับขั้นตอนและประสบการณ์ของผู้ใช้ขณะพยายามบรรลุเป้าหมายหนึ่ง ๆ ตั้งแต่ต้นจนจบ โดยแสดงทั้งสิ่งที่ผู้ใช้ทำ คิด รู้สึก และจุดที่มีปฏิสัมพันธ์กับระบบ (touchpoints) จุดเด่นคือทำให้ทีมเห็น “ภาพรวมของประสบการณ์” และค้นพบ pain points ที่ซ่อนอยู่ตามรอยต่อระหว่างขั้นตอน

2.2 องค์ประกอบของ Journey Map

Journey map ส่วนใหญ่จัดเป็นตาราง โดยให้ คอลัมน์ เป็นช่วงเวลา (stages) และ แถว เป็นมิติต่าง ๆ ที่เราติดตาม ได้แก่ การกระทำ (Actions), ความคิด/คำพูด (Thoughts), จุดสัมผัส (Touchpoints), เส้นกราฟอารมณ์ (Emotion curve), จุดเจ็บปวด (Pain points) และ โอกาส (Opportunities)

2.3 ต่อยอดจาก Empathy Map สู่ Journey Map

นี่คือหัวใจของบทนี้ — Empathy Map จากบทที่ 4 ไม่ได้ถูกทิ้งไป แต่ถูกนำมา “แปลง” เป็นวัตถุดิบของ Journey Map โดยตรง มิติ Feels กลายเป็นเส้นกราฟอารมณ์ มิติ Pains กลายเป็น pain points ตามช่วง ส่วน Does และ Says ช่วยกำหนด actions และ touchpoints

ตาราง: Feels/Pains ของ “พิม” ไปปรากฏที่ช่วงใดของเส้นทาง

ข้อมูลจาก Empathy Map (บทที่ 4)ประเภทไปปรากฏที่ช่วงของ Journey Map
ตื่นตระหนก ใจหายวาบFeelsช่วงที่ 1: รู้ว่าสัตว์หาย (อารมณ์ดิ่งลง)

เดินหารอบหมู่บ้าน ถ่ายรูปไปด้วยDoesช่วงที่ 2: เป็น Actions
“ขอแชร์ด่วน ๆ นะคะ”Saysช่วงที่ 3: กระจายข่าว (touchpoint โซเชียล)
ข่าวกระจายช้า กระจัดกระจายPainsช่วงที่ 3–4: กระจายข่าว/รอเบาะแส

ช่วงที่อารมณ์ดิ่งต่ำสุด (ช่วง 3–4) คือจุดที่ผู้ใช้ทุกข์ที่สุด จึงเป็น “โอกาสทอง” ที่การออกแบบของเราจะสร้างคุณค่าได้สูงสุด — โอกาสเหล่านี้จะกลายเป็นฟีเจอร์หลักของแอปในบทต่อไป

2.5 ขั้นตอนการสร้าง Journey Map

เริ่มจาก (1) เลือก Persona และสถานการณ์ (scenario) ที่ชัดเจน (2) แบ่งช่วงเวลา (stages) ของเส้นทาง (3) เติม Actions, Thoughts, Touchpoints จาก Does/Says ใน Empathy Map (4) วาดเส้นกราฟอารมณ์จาก Feels (5) ระบุ pain points จาก Pains และ (6) แปลง pain points เป็นโอกาสในการออกแบบ

⚠️ ข้อผิดพลาดที่พบบ่อย
  • ทำ journey map โดยไม่อิงข้อมูลจริง — กลายเป็นเส้นทางในจินตนาการของทีม ไม่ใช่ของผู้ใช้
  • ใส่แต่ขั้นตอนบนหน้าจอ ลืมช่วง “ก่อน” และ “หลัง” ใช้แอป ทั้งที่ pain points มักอยู่ตรงนั้น
  • ลืมเส้นกราฟอารมณ์ ทำให้มองไม่เห็นว่าจุดไหนที่ผู้ใช้ทุกข์ที่สุดและควรแก้ก่อน

เชื่อมโยงสู่การพัฒนาเว็บ: จากช่วงเวลาในเส้นทางสู่ลำดับฟีเจอร์

โอกาสในการออกแบบที่พบในแต่ละช่วง สามารถจัดเก็บอย่างมีโครงสร้างเพื่อแปลงเป็น backlog ของฟีเจอร์ที่จัดลำดับความสำคัญตามความรุนแรงของ pain point ซึ่งเชื่อมโดยตรงกับการวางแผนพัฒนาเว็บแอป

เชื่อมจากบทก่อนหน้า

บทนี้ต่อยอด Empathy Map ของ “พิม” จาก บทที่ 4 โดยตรง — มิติ Feels (ตื่นตระหนก, ท้อ) กลายเป็นเส้นกราฟอารมณ์ และ Pains (ไม่รู้จะเริ่มตรงไหน, ข่าวกระจายช้า) กลายเป็น pain points ตามช่วงเวลา ดังที่แสดงในตารางหัวข้อ 2.3 ทำให้ข้อมูลผู้ใช้ไหลต่อเนื่องโดยไม่ขาดตอน

สะพานสู่บทต่อไป

โอกาสในการออกแบบ ที่ค้นพบในแถวสุดท้ายของ journey map (เช่น “ฟอร์มแจ้งหายสั้น”, “รวมเบาะแสไว้ที่เดียว”) จะกลายเป็นรายการฟังก์ชัน/เนื้อหา ที่นำไปจัดโครงสร้างใน บทที่ 6: สถาปัตยกรรมข้อมูลและการไหลของหน้าจอ

3. สรุปท้ายบท

  • User Journey Map แสดงประสบการณ์ผู้ใช้แบบ end-to-end ตามแกนเวลา ช่วยค้นพบ pain points ตามรอยต่อระหว่างขั้นตอน
  • องค์ประกอบหลัก: ช่วงเวลา, การกระทำ, ความคิด, touchpoints, เส้นกราฟอารมณ์, pain points และโอกาส
  • Empathy Map ต่อยอดเป็น Journey Map — Feels→เส้นอารมณ์, Pains→pain points, Does→actions, Says→touchpoints
  • ช่วงที่ อารมณ์ต่ำสุด คือโอกาสที่การออกแบบจะสร้างคุณค่าได้มากที่สุด
  • Journey Map ต้องอิงข้อมูลจริง และครอบคลุมทั้งช่วง “ก่อน–ระหว่าง–หลัง” การใช้งาน
❓

4. คำถามทบทวน (ไม่เก็บคะแนน)

User Journey Map ต่างจาก Empathy Map อย่างไร และทั้งสองเชื่อมโยงกันอย่างไร
องค์ประกอบของ Journey Map มีอะไรบ้าง และเหตุใด “เส้นกราฟอารมณ์” จึงสำคัญต่อการจัดลำดับความสำคัญ
จากกรณีศึกษา มิติ Feels และ Pains ของพิมไปปรากฏที่ช่วงใดของเส้นทางบ้าง
เหตุใดช่วงที่อารมณ์ผู้ใช้ต่ำที่สุดจึงถือเป็น “โอกาสทอง” ในการออกแบบ
ลองร่าง journey map ของ “ผู้พบเห็นสัตว์จร” ว่าจะมีกี่ช่วง และ pain point หลักอยู่ตรงไหน

5. ขั้นตอน Workshop ในคาบ

กิจกรรมในคาบ (ปฏิบัติ 2 ชั่วโมง) ทำเป็นกลุ่มเดิม โดยใช้กระดาษแผ่นใหญ่/sticky note หรือ FigJam/Miro ห้ามใช้เครื่องมือ AI

  1. วอร์มอัป: “เส้นทางกาแฟแก้วโปรด” (10 นาที)
    แต่ละคนวาด journey สั้น ๆ ของการซื้อกาแฟ 1 แก้ว พร้อมเส้นอารมณ์ เพื่อเข้าใจโครงสร้าง
  2. ทบทวนแนวคิดหลักร่วมกัน (15 นาที)
    ทบทวนองค์ประกอบ journey map และวิธีต่อยอดจาก Empathy Map แล้วจดประเด็นที่จะนำไปใช้
  3. ทบทวน Empathy Map (บทที่ 4) (15 นาที)
    นำ Feels/Pains/Does/Says ของ Persona มาแปะ เตรียมแปลงเป็นวัตถุดิบ journey
  4. แบ่งช่วงเวลา (Stages) (15 นาที)
    กำหนดช่วงเวลาของเส้นทางผู้ใช้ตั้งแต่ต้นจนจบ (รวมช่วงก่อน–หลังใช้แอป)
  5. เติมตารางและวาดเส้นอารมณ์ (30 นาที)
    เติม Actions, Thoughts, Touchpoints, Pain points แต่ละช่วง แล้ววาดเส้นกราฟอารมณ์จาก Feels
  6. ระบุโอกาสในการออกแบบ (20 นาที)
    แปลง pain points เป็นโอกาส และทำเครื่องหมายช่วงที่อารมณ์ต่ำสุดเป็นจุดสำคัญ
  7. Peer Review & สรุป (15 นาที)
    สลับผลงานกับอีกกลุ่ม ตรวจว่าทุกข้อมูลอิงจาก Empathy Map จริงหรือไม่ แล้วร่วมสรุปบทเรียน

  2. ตารางเชื่อมโยง Empathy Map → Journey Map ระบุว่า Feels/Pains แต่ละข้อไปปรากฏที่ช่วงใด
  3. เส้นกราฟอารมณ์ ที่วาดชัดเจน และทำเครื่องหมายจุดที่อารมณ์ต่ำสุด
  4. โอกาสในการออกแบบ 3–5 ข้อ ที่จัดลำดับความสำคัญตามความรุนแรงของ pain point
  5. สะท้อนคิด (Reflection) 3–5 บรรทัด: การมองเส้นทางแบบ end-to-end เปลี่ยนมุมมองของกลุ่มอย่างไร

เกณฑ์ประเมิน: ความต่อเนื่องจาก Empathy Map (30%) · ความครบถ้วนของมิติ (25%) · คุณภาพการวิเคราะห์ pain/โอกาส (25%) · การสะท้อนคิด (20%)
