1. บทนำ

“สีและตัวอักษรพูดกับผู้ใช้ก่อนที่ข้อความใด ๆ จะถูกอ่านเสียอีก” — ก่อนผู้ใช้จะอ่านคำว่า ‘แจ้งหาย’ เขารับรู้ ‘ความเร่งด่วน’ จากสีและขนาดไปแล้ว เราจะใช้สองสิ่งนี้สื่อสารอย่างตั้งใจได้อย่างไร?

ในบทที่ 7 เราจัดวางองค์ประกอบด้วยลำดับชั้นและกริดแล้ว แต่หน้าจอยังเป็นโครงร่างขาวดำ บทนี้จะเติม “ภาษาภาพ” สองอย่างที่ทรงพลังที่สุดในงาน UI คือ สี และ ตัวอักษร ซึ่งเป็นเครื่องมือเสริมลำดับชั้น สื่ออารมณ์ และสร้างเอกลักษณ์ของแบรนด์

บทนี้กินเวลา 2 สัปดาห์: สัปดาห์แรกเน้นทฤษฎีสีและการสร้างชุดสี สัปดาห์ที่สองเน้นการใช้ตัวอักษรและการสร้างระบบ type เนื้อหามีทฤษฎีค่อนข้างมาก จึงแบ่งเป็นสองส่วนใหญ่ พร้อมตัวอย่างประกอบหลากหลายรูปแบบ

💭 ชวนคิดก่อนเริ่ม
ถ้าแอปค้นหาสัตว์เลี้ยงหายใช้สีชมพูพาสเทลและฟอนต์ลายมือทั้งหมด ผู้ใช้ที่กำลังตื่นตระหนกจะรู้สึกอย่างไร? สีและตัวอักษรควร “เข้ากับอารมณ์ของสถานการณ์” หรือไม่?

2. ทฤษฎีสี (Color Theory)

2.1 มิติของสี: Hue, Saturation, Brightness

ทุกสีอธิบายได้ด้วย 3 มิติ — Hue (เนื้อสี) คือชนิดของสี เช่น แดง เขียว น้ำเงิน, Saturation (ความอิ่มตัว) คือความสดของสี (สดจัด ↔ หม่น/เทา), และ Brightness/Value (ความสว่าง) คือความสว่าง-มืดของสี โมเดลนี้เรียกว่า HSB (หรือ HSV) ซึ่งเข้าใจง่ายกว่าการคิดเป็นค่าตัวเลข RGB

2.2 โมเดลสี: RGB, CMYK และ HEX

สื่อต่างชนิดใช้โมเดลสีต่างกัน RGB (Red-Green-Blue) เป็นระบบ บวก (additive) ใช้กับจอภาพ ยิ่งผสมแสงมากยิ่งสว่างจนเป็นสีขาว ส่วน CMYK (Cyan-Magenta-Yellow-Key/black) เป็นระบบ ลบ (subtractive) ใช้กับงานพิมพ์ ยิ่งผสมหมึกมากยิ่งมืดลง สำหรับงานเว็บและแอปเราใช้ RGB และมักเขียนเป็นรหัส HEX เช่น #BB7D10

โมเดลระบบใช้กับตัวอย่างค่า
RGBบวก (แสง)จอภาพ เว็บ แอปrgb(187, 125, 16)
HEXบวก (เขียนย่อของ RGB)โค้ดเว็บ/CSS#BB7D10
HSL/HSBบวก (เชิงการรับรู้)เครื่องมือออกแบบhsl(38, 84%, 40%)
CMYKลบ (หมึก)งานพิมพ์C0 M33 Y91 K27

2.3 วงล้อสีและชนิดของสี

วงล้อสี (Color Wheel) จัดเรียงเนื้อสีเป็นวงกลม ช่วยให้เห็นความสัมพันธ์ระหว่างสี แบ่งได้เป็น แม่สี (Primary) = แดง เหลือง น้ำเงิน, สีขั้นที่สอง (Secondary) = ส้ม เขียว ม่วง (เกิดจากผสมแม่สี), และ สีขั้นที่สาม (Tertiary) = สีที่อยู่ระหว่างแม่สีกับสีขั้นที่สอง

2.4 ชุดสีที่กลมกลืน (Color Harmony)

การเลือกสีที่ “เข้ากัน” ทำได้ด้วยการอ้างอิงตำแหน่งบนวงล้อสี รูปแบบที่นิยมมีดังนี้

2.5 อุณหภูมิสีและจิตวิทยาสี

อุณหภูมิสี แบ่งเป็นสีโทนร้อน (แดง ส้ม เหลือง) ที่ให้ความรู้สึกอบอุ่น ตื่นเต้น เร่งด่วน และสีโทนเย็น (เขียว น้ำเงิน ม่วง) ที่ให้ความรู้สึกสงบ น่าเชื่อถือ นอกจากนี้แต่ละสียังมี ความหมายเชิงจิตวิทยา ที่ควรเลือกใช้ให้สอดคล้องกับบุคลิกของผลิตภัณฑ์ (ทั้งนี้ความหมายอาจต่างกันตามวัฒนธรรม)

สีความรู้สึก/ความหมายที่พบบ่อยมักใช้กับ
แดงเร่งด่วน อันตราย พลังงาน ความรักการแจ้งเตือน ข้อผิดพลาด ปุ่มสำคัญ
ส้มกระตือรือร้น เป็นมิตร อบอุ่นปุ่ม CTA โปรโมชัน
เหลืองสดใส มองเห็นง่าย คำเตือนป้ายเตือน ไฮไลต์
เขียวสำเร็จ ปลอดภัย ธรรมชาติ เติบโตสถานะสำเร็จ การเงิน สุขภาพ
น้ำเงินน่าเชื่อถือ มั่นคง สงบ มืออาชีพธนาคาร เทคโนโลยี องค์กร
ม่วงหรูหรา สร้างสรรค์ ลึกลับแบรนด์พรีเมียม ความงาม
กรณีศึกษา: แอปค้นหาสัตว์เลี้ยงหาย

เลือกสีหลักเป็น น้ำเงิน-เขียว ที่ให้ความรู้สึกน่าเชื่อถือและสงบ (ช่วยปลอบใจผู้ใช้ที่ตื่นตระหนก) แต่ใช้ ส้ม/แดง เป็นสีเน้นเฉพาะปุ่ม “แจ้งสัตว์หาย” เพื่อสื่อความเร่งด่วน — เป็นการจับคู่อารมณ์ของสีให้ตรงกับงาน

2.6 การสร้างชุดสี UI และกฎ 60-30-10

2.7 สีกับการเข้าถึง (Accessibility)

สีที่สวยแต่ตัดกันน้อยทำให้อ่านยาก โดยเฉพาะผู้สูงอายุหรือผู้มีสายตาเลือนราง มาตรฐาน WCAG กำหนด อัตราส่วนความตัดกัน (contrast ratio) ระหว่างข้อความกับพื้นหลัง โดยข้อความปกติควรมีอัตราอย่างน้อย 4.5:1 (ระดับ AA) และข้อความใหญ่อย่างน้อย 3:1

ข้อความบนพื้นเข้มcontrast ≈ 6.1:1 — ผ่าน AA ✓
ข้อความเข้มบนพื้นอ่อนcontrast ≈ 13:1 — ผ่าน AAA ✓
ข้อความอ่อนบนพื้นกลางcontrast ≈ 1.8:1 — ไม่ผ่าน ✗

นอกจากนี้ ผู้ใช้ราว 1 ใน 12 ของผู้ชายมีภาวะ ตาบอดสี (มักแยกแดง-เขียวยาก) จึงไม่ควรสื่อความหมายด้วย “สีเพียงอย่างเดียว” เช่น สถานะผิดพลาดควรมีทั้งสีแดง และ ไอคอน/ข้อความกำกับ

⚠️ ข้อผิดพลาดที่พบบ่อย (เรื่องสี)
  • ใช้สีมากเกินไปจนไม่มีลำดับชั้น — ควรจำกัดชุดสีหลักไม่กี่สี
  • ข้อความสีเทาอ่อนบนพื้นขาว contrast ต่ำ อ่านไม่ออก
  • สื่อสถานะด้วยสีอย่างเดียว ผู้ใช้ตาบอดสีแยกไม่ออก
🔤

3. การใช้ตัวอักษร (Typography)

3.1 กายวิภาคของตัวอักษร

การเข้าใจส่วนประกอบของตัวอักษรช่วยให้สื่อสารและเลือกฟอนต์ได้แม่นยำ คำศัพท์สำคัญได้แก่ baseline (เส้นฐานที่ตัวอักษรวางอยู่), x-height (ความสูงของตัวพิมพ์เล็ก), cap height (ความสูงตัวพิมพ์ใหญ่), ascender (ส่วนที่สูงเลย x-height เช่นหัว b, d) และ descender (ส่วนที่ต่ำกว่า baseline เช่นหาง g, p)

3.3 คุณสมบัติของตัวอักษรและลำดับชั้น (Type Scale)

การจัดตัวอักษรให้สื่อลำดับชั้นใช้คุณสมบัติหลายอย่างร่วมกัน: ขนาด (size), น้ำหนัก (weight) เช่น Regular/Bold, ระยะบรรทัด (line-height/leading), ระยะระหว่างตัวอักษร (letter-spacing/tracking) และ ความยาวบรรทัด (line length/measure) ที่เหมาะสมราว 45–75 ตัวอักษรต่อบรรทัด

เรามักกำหนด “ระดับ” ของตัวอักษรเป็น type scale โดยใช้อัตราส่วนคงที่ (เช่น 1.25) เพื่อให้ขนาดต่างกันอย่างมีจังหวะ

H1 · 32px Boldแจ้งสัตว์เลี้ยงหาย
H2 · 25px Semiboldรายละเอียดประกาศ
H3 · 20px Semiboldข้อมูลสัตว์
Body · 16px Regularเนื้อหาทั่วไปสำหรับอ่าน อ่านง่ายที่ขนาด 16px
Caption · 13px Regularข้อความกำกับ/หมายเหตุขนาดเล็ก

3.4 ความอ่านง่าย การจับคู่ฟอนต์ และตัวอักษรไทย

Legibility คือความ “แยกแยะตัวอักษรแต่ละตัวได้ง่าย” ส่วน Readability คือความ “อ่านเป็นข้อความได้ลื่นไหล” ทั้งสองได้รับผลจากขนาด ระยะบรรทัด และความตัดกันของสี การ จับคู่ฟอนต์ (font pairing) ที่ดีมักใช้ฟอนต์ไม่เกิน 2 แบบ เช่น ฟอนต์หัวเรื่องไม่มีหัว + ฟอนต์เนื้อหามีหัว เพื่อให้ต่างกันพอเห็นลำดับชั้นแต่ยังกลมกลืน

🔑 ข้อควรระวังเฉพาะตัวอักษรภาษาไทย
ภาษาไทยมีสระบน-ล่างและวรรณยุกต์ที่ต้องการ ระยะบรรทัด (line-height) มากกว่าภาษาอังกฤษ (แนะนำ ~1.6–1.8) มิฉะนั้นวรรณยุกต์จะชนกับบรรทัดถัดไป และควรเลือกฟอนต์ที่จัดวางวรรณยุกต์ได้ถูกต้องเพื่อเลี่ยงปัญหา “วรรณยุกต์ลอย”
⚠️ ข้อผิดพลาดที่พบบ่อย (เรื่องตัวอักษร)
  • ใช้ฟอนต์หลายแบบเกินไป ทำให้หน้าจอดูไม่เป็นเอกภาพ
  • ตัวอักษรเล็กเกินไป (ต่ำกว่า 14–16px) หรือบรรทัดชิดเกินไป อ่านยาก
  • บรรทัดยาวเกินไป ตาผู้อ่านหลงบรรทัด
  • ใช้ฟอนต์ตกแต่ง (script) กับเนื้อหายาว
กรณีศึกษา: Style Guide เบื้องต้นของแอป

สี: Primary น้ำเงิน-เขียว (#1F6F8B) + Accent ส้ม (#E8743B) สำหรับปุ่มแจ้งหาย + Semantic (success/warning/error)   ตัวอักษร: หัวเรื่องใช้ฟอนต์ไทยไม่มีหัว (เช่น Prompt) เนื้อหาใช้ฟอนต์มีหัว (เช่น Sarabun) ขนาดฐาน 16px line-height 1.7

เชื่อมโยงสู่การพัฒนาเว็บ: Design Tokens ด้วย CSS Variables

ชุดสีและ type scale ที่ออกแบบไว้ แปลงเป็น “design tokens” ในรูปตัวแปร CSS ได้โดยตรง ทำให้ทีมพัฒนาใช้ค่าเดียวกันทั้งระบบและแก้ไขจุดเดียว

:root {
  /* สี */
  --color-primary: #1F6F8B;
  --color-accent:  #E8743B;   /* ปุ่มแจ้งหาย */
  --color-success: #2E8B57;
  --color-error:   #C0392F;
  /* ตัวอักษร (type scale 1.25) */
  --font-base: 'Sarabun', sans-serif;
  --text-h1: 2rem;      /* 32px */
  --text-body: 1rem;    /* 16px */
  --leading: 1.7;        /* line-height สำหรับภาษาไทย */
}

เชื่อมจากบทก่อนหน้า

ใน บทที่ 7 เราจัดวางองค์ประกอบและสร้างลำดับชั้นด้วยขนาด/ตำแหน่งบนโครงร่างขาวดำ บทนี้เติม สีและตัวอักษร เพื่อ เสริมลำดับชั้นเดิมให้ชัดขึ้น เช่น ปุ่มที่เด่นด้วยขนาดอยู่แล้ว เด่นยิ่งขึ้นด้วยสี Accent และหัวเรื่องเด่นขึ้นด้วยฟอนต์/น้ำหนัก

สะพานสู่บทต่อไป

ชุดสีและระบบตัวอักษร (Style Guide) ที่ได้ในบทนี้ จะถูกนำไปใช้จริงเมื่อสร้าง บทที่ 9: Wireframe และ Interactive Prototype — เปลี่ยนโครงร่างขาวดำให้กลายเป็นต้นแบบความละเอียดสูงที่มีสีและตัวอักษรครบ

4. สรุปท้ายบท

  • สีอธิบายด้วย 3 มิติ Hue–Saturation–Brightness; โมเดล RGB/HEX ใช้กับจอ CMYK ใช้กับงานพิมพ์
  • วงล้อสี เป็นฐานของ ชุดสีที่กลมกลืน (complementary, analogous, triadic, monochromatic ฯลฯ)
  • เลือกสีให้ตรงกับ อารมณ์/จิตวิทยา ของงาน และจัดสัดส่วนด้วยกฎ 60-30-10
  • ตรวจ contrast ตาม WCAG (≥4.5:1) และไม่สื่อความหมายด้วยสีอย่างเดียว (เผื่อผู้ใช้ตาบอดสี)
  • เข้าใจ กายวิภาคและประเภทตัวอักษร ทั้งอังกฤษ (serif/sans/mono) และไทย (มีหัว/ไม่มีหัว)
  • สร้าง type scale ด้วยขนาด/น้ำหนัก/ระยะบรรทัด — ภาษาไทยต้องการ line-height สูงกว่า และจับคู่ฟอนต์ไม่เกิน 2 แบบ
❓

5. คำถามทบทวน (ไม่เก็บคะแนน)

RGB กับ CMYK ต่างกันอย่างไร และเหตุใดงานเว็บจึงใช้ RGB/HEX
อธิบายความต่างของชุดสีแบบ Complementary, Analogous และ Monochromatic พร้อมความรู้สึกที่ให้
กฎ 60-30-10 คืออะไร และช่วยให้หน้าจอสมดุลอย่างไร
เหตุใดจึงไม่ควรสื่อความหมายด้วยสีเพียงอย่างเดียว และ contrast ratio ขั้นต่ำของ WCAG ระดับ AA คือเท่าใด
ฟอนต์ไทยแบบมีหัวและไม่มีหัวต่างกันอย่างไร และควรเลือกใช้อย่างไรในแอปค้นหาสัตว์เลี้ยงหาย
เหตุใดตัวอักษรภาษาไทยจึงต้องการระยะบรรทัด (line-height) มากกว่าภาษาอังกฤษ
▶ ส่วนที่ 2 — กิจกรรมและงานในคาบ
🛠️

6. ขั้นตอน Workshop (2 สัปดาห์)

บทนี้มี workshop 2 คาบ โดยใช้ Figma/Coolors และตัวตรวจ contrast ห้ามใช้เครื่องมือ AI

📅 สัปดาห์ที่ 10 — ชุดสี (Color)
  1. วอร์มอัป: “สีนี้รู้สึกอย่างไร” (10 นาที)
    ดูตัวอย่างสี/แอปจริงที่กำหนดให้ แล้วช่วยกันในกลุ่มทายอารมณ์และบุคลิกของแบรนด์จากสี
  2. ทบทวนทฤษฎีสีร่วมกัน (20 นาที)
    ทบทวนมิติของสี โมเดลสี วงล้อสี harmony และ accessibility แล้วจดประเด็นที่จะนำไปใช้
  3. เลือกชุดสีของแอป (35 นาที)
    เลือกรูปแบบ harmony และกำหนด Primary/Secondary/Accent/Neutral/Semantic ให้สอดคล้องอารมณ์ของกรณีศึกษา
  4. ตรวจ contrast (25 นาที)
    ทดสอบคู่สีข้อความ-พื้นหลังให้ผ่าน WCAG AA และตรวจการมองเห็นแบบตาบอดสี
  5. Peer Review (20 นาที)
    สลับชุดสีกับอีกกลุ่ม ตรวจความกลมกลืนและการเข้าถึง
📅 สัปดาห์ที่ 11 — ตัวอักษร (Typography)
  1. วอร์มอัป: “จับคู่ฟอนต์” (10 นาที)
    ดูตัวอย่างการจับคู่ฟอนต์ที่ดี/ไม่ดี แล้ววิจารณ์
  2. ทบทวน Typography ร่วมกัน (20 นาที)
    ทบทวนกายวิภาค ประเภทฟอนต์ type scale และข้อควรระวังภาษาไทย แล้วจดประเด็นที่จะนำไปใช้
  3. สร้าง Type Scale (35 นาที)
    กำหนดฟอนต์หัวเรื่อง/เนื้อหา และขนาด H1–Caption พร้อม line-height สำหรับภาษาไทย
  4. ทดลองใช้กับหน้าจอจริง (30 นาที)
    นำชุดสี + type scale ไปลองใส่ใน wireframe หน้า “รายละเอียดประกาศ”
  5. Peer Review & สรุป (15 นาที)
    ตรวจความอ่านง่ายและความเป็นเอกภาพกับอีกกลุ่ม แล้วร่วมสรุปและทบทวนโจทย์งานที่ต้องส่ง
📤

7. งานที่ต้องส่ง (Assignment 8)

⏰ กำหนดส่ง: ก่อนเริ่มคาบสัปดาห์ที่ 12

ชิ้นงาน: “Style Guide เบื้องต้น (สี + ตัวอักษร)”

เป็นชิ้นงานชิ้นที่ 8 ของ Design Portfolio ส่งเป็นไฟล์ PDF ประกอบด้วย:

  1. ชุดสี Primary/Secondary/Accent/Neutral/Semantic พร้อมรหัส HEX และระบุรูปแบบ harmony ที่ใช้
  2. เหตุผลการเลือกสี เชื่อมโยงกับอารมณ์/บุคลิกของแอปและกรณีศึกษา
  3. ผลตรวจ contrast ของคู่สีหลักอย่างน้อย 3 คู่ (ระบุอัตราส่วนและระดับ AA/AAA)
  4. ระบบตัวอักษร: ฟอนต์หัวเรื่อง/เนื้อหา + type scale (H1–Caption) + line-height
  5. ตัวอย่างการใช้งานจริง นำสี+ตัวอักษรไปใส่ใน 1 หน้าจอจาก wireframe
  6. สะท้อนคิด (Reflection) 3–5 บรรทัด

เกณฑ์ประเมิน: ความกลมกลืนของชุดสี (25%) · การเข้าถึง/contrast (20%) · ระบบตัวอักษรและลำดับชั้น (25%) · ความสอดคล้องกับกรณีศึกษา (15%) · การนำไปใช้จริง+สะท้อนคิด (15%)
